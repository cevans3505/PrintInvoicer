# Phase 1, Plan 01: The job list picture and the one-command pipeline

## Phase Goal

ROADMAP Goal line (verbatim): "A visitor to the README can see what PrintInvoicer looks like and what it produces, and a
maintainer can regenerate those images with one command after UI changes."

The ROADMAP Goal line is not written as a user story. The story below restates its two actors and outcomes without adding
scope (the "at a glance" outcome comes from PROJECT.md and the CONTEXT.md specifics). Run `/gsd-mvp-phase 1` to replace it
with a canonical story if wanted.

**As a** visitor to the README, **I want to** see what PrintInvoicer looks like and what it produces, **so that** I
understand the app at a glance.
**As a** maintainer, **I want to** regenerate those images with one command after UI changes, **so that** the README
stays in step with the app.

This plan delivers the job list picture (SHOW-01) and the whole regeneration pipeline (SHOW-04) for it. Plan 01-02 adds
the editor and invoice pictures and the README regeneration note on the same pipeline.

<objective>
Prove the README image pipeline end to end on the job list, then make that picture show every job state.

Purpose: a visitor sees the job list near the top of the README; a maintainer rebuilds it with `.\make-readme-images.ps1`,
offscreen, from sample data, and a normal test run or CI never touches the committed file.

Output: `WpfHost.RenderPng`, `ReadmeImageTests`, `make-readme-images.ps1`, `docs/images/main-jobs.png`, the README
`## What it looks like` section, a fourth (finalized and paid) sample job with fixed dates, and updated ScreenTests asserts.
</objective>
