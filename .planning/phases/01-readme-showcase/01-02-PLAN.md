# Phase 1, Plan 02: The editor and invoice pictures, and the regeneration note

## Phase Goal

ROADMAP Goal line (verbatim): "A visitor to the README can see what PrintInvoicer looks like and what it produces, and a
maintainer can regenerate those images with one command after UI changes." The user-story restatement and the note about
`/gsd-mvp-phase 1` are in plan 01-01.

**As a** visitor to the README, **I want to** see what PrintInvoicer looks like and what it produces, **so that** I
understand the app at a glance.
**As a** maintainer, **I want to** regenerate those images with one command after UI changes, **so that** the README
stays in step with the app.

This plan adds the job editor picture (SHOW-02) and invoice page 1 (SHOW-03) to the pipeline plan 01-01 proved, makes the
one command rebuild all three (SHOW-04), and documents it (SHOW-05).

<objective>
Extend the proven pipeline to the job editor and the invoice, then document how to rebuild the pictures.

Purpose: a visitor sees what the app looks like while pricing a job and what the customer receives; a maintainer knows
how and when to rebuild the pictures.

Output: `RenderJobEditor` and `RenderInvoice` in `ReadmeImageTests`, `docs/images/job-editor.png`,
`docs/images/invoice-page-1.png`, the README pictures and `### Regenerating the README images`, an AUDITING.md bullet,
and the CI comment count.
</objective>

## Flagged Assumptions

These are explicit; unless marked resolved, the verifier should confirm or raise them.

- **A-1 (edge probe, SHOW-03, resolved):** the edges of the invoice picture are the fixed page size (letter at 110 DPI,
  asserted as exactly 935 x 1210) and the page count, asserted as exactly one with `Assert.Single` (the RESEARCH probe
  rendered 1 page). If a later change makes the Wire Brush invoice run to two pages, the generator fails before writing
  anything instead of silently showing only page 1.
- **A-2 (edge probe, SHOW-05, unclassified, unresolved):** the README instructions are checked by text presence (heading,
  command, folder, `git status docs/images`) and an end-of-phase read-through, not by an executable doc test.
- **A-3 (planner choice):** the in-memory invoice is dated 2026-10-31, not the 2026-10-30 example in RESEARCH, because plan
  01-01 fixes the job's created date at 2026-10-31 and an invoice should not predate its job.
- **A-4 (planner choice, CONTEXT discretion):** the pictures sit before the "Personal project" and "AI use disclosure"
  notices, whose text stays byte-identical. Moving the section below the notices is a one-edit change if wanted.
- **A-5 (RESEARCH A1):** GitHub scales wide README images to the page width, so the 2x window pictures need no width
  attribute; the invoice is shown at `width="480"` and links to the full-size file.
